# PODEM ATPG + Parallel-Pattern Fault Simulation on ISCAS-85

A self-contained, stdlib-only Python implementation of classical
automatic test-pattern generation for combinational circuits:

* **PODEM** (Path-Oriented Decision Making, Goel 1981) stuck-at ATPG with
  event-driven implication, SCOAP-guided backtrace, sound X-path pruning
  and randomized restarts,
* a **parallel-pattern (bit-parallel) fault simulator** (PPSFP) — every
  signal is a Python big-int with one bit per test pattern, so a batch of
  1024 patterns simulates in the time of one,
* **equivalence + dominance fault collapsing** with per-rule proof
  obligations validated in the test suite,
* a **naive scalar simulator** kept as an independent reference engine;
  the test suite cross-validates all three against each other
  (exhaustively on c17, statistically on larger circuits).

Runs on the eleven **ISCAS-85 combinational benchmark circuits**
(`c17` … `c7552`, committed under `benchmarks/`), from the 6-gate c17 to
the 3,512-gate c7552. One command produces per-circuit test-vector sets,
coverage reports and a summary table.

```
$ python tools/run_atpg.py --circuits all
[c17]  faults 34  -> collapsed 16  | coverage 100.0% | 5 patterns
[c432] faults 864 -> collapsed 449 | coverage 99.1% | ...
...
TOTALS: collapsed coverage NN.N% (N/NNNN) | full coverage NN.N% | ...
```

## Why this exists

Design-for-Test is a preferred qualification for silicon design and
verification roles, and the only honest way to claim DFT fundamentals is
to build the machinery: fault models, ATPG search, fault simulation and
coverage accounting. This repo is that build — an educational-scale ATPG
prototype, not a commercial tool. Every number in `results/` is
regenerated by `tools/run_atpg.py` and every bolded claim is greppable
in the committed reports and the test suite.

Engineering decisions, the reasoning behind the fault-collapsing
direction, and the two subtle bugs that differential testing caught
(a D-frontier definition error that made PODEM call 335 testable faults
redundant, and an unsound X-path pruning rule) are documented in
[docs/notes.md](docs/notes.md).

## Reproducing

```bash
python -m unittest discover -s tests -t .      # full validation suite
python tools/run_atpg.py --circuits all        # full run -> results/
python tools/run_atpg.py --circuits c17,c432   # quick smoke run
```

* Python 3.11+ (developed on 3.13), **no third-party dependencies**.
* Deterministic: fault order, heuristics and X-fill are seeded
  (`--seed`, default 42); reruns reproduce identical vectors and
  coverage.

### What the runner does per circuit

1. parse the `.bench` netlist and expand explicit fanout stems/branches
   (the `.bench` format has none; c432 expands to exactly 432 nets →
   864 full stuck-at faults, matching the classic accounting),
2. generate the full fault list (every net × {s-a-0, s-a-1}) and collapse
   it with equivalence + dominance rules,
3. run PODEM per collapsed fault with periodic fault dropping; aborted
   faults get randomized-restart attempts,
4. **cross-check**: every PODEM vector is re-verified by the independent
   bit-parallel simulator; redundant faults must never be detected;
   compaction must not lose coverage — violations abort the run loudly,
5. reverse-order static compaction of the vector set,
6. write vectors + `results/summary.{json,md}` with detected /
   redundant / aborted / coverage per circuit.

## Honesty notes

* **redundant** means PODEM exhausted its decision space (proof of
  untestability); **aborted** means the backtrack budget was exhausted —
  the fault may or may not be testable, and it is reported as such.
  Nothing is silently dropped or inflated.
* Full-list coverage is derived through the collapse representative
  mapping; the mapping property (every test for a representative detects
  every fault it covers) is checked exhaustively on c17 and against
  random pattern sets on c432/c499/c880 in the test suite.
* c432 is a useful honesty benchmark: it contains 4 stuck-at faults that
  200,000 random patterns never detect (both simulators agree); within a
  bounded backtrack budget PODEM cannot *prove* their redundancy, so
  they surface as `aborted` rather than being claimed either way.

## Benchmarks provenance

The ISCAS-85 benchmarks (F. Brglez and H. Fujiwara, ISCAS 1985) have
been freely redistributed for research and education for decades. Files
are unmodified `.bench` versions from the public mirror at
`pld.ttu.ee/~maksim/benchmarks` — see `benchmarks/README.md`. The parser
test suite asserts every circuit's PI/PO/gate counts against the
published statistics table.
